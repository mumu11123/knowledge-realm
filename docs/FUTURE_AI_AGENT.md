# 未来 AI Agent 扩展

> 阶段更新：以下保留 V0.1 的原始规划。V0.2 已实现 Spring AI、轻量 RAG、真实只读工具、授权浏览器会话、草稿生成与人工发布。现状见 [AI_ARCHITECTURE.md](AI_ARCHITECTURE.md) 与 [AI_GUIDE.md](AI_GUIDE.md)。正式账户、多用户角色体系、向量检索和更丰富内容仍是后续工作。

V0.1 不引入 Spring AI、向量数据库、RAG、MCP、工具调用框架、Redis 或消息队列。

## 保留的业务边界

LearningService 提供科目、章节、知识简介、故事、判分和知识卡等清晰方法；Mapper 负责持久化，HTTP VO 与数据库投影分离。未来 AI 适配层可调用服务，不应直接拼接 SQL 或修改正确答案。

游客进度通过 StoragePort 与前端状态函数封装。引入账户时先实现身份认证、服务端学习记录和迁移策略，再把浏览器数据通过明确的用户操作导入账户，处理时间戳、重复故事和收藏合并；在此之前不承诺跨设备同步。

## 建议顺序

1. 完善内容审核、来源记录与数据结构教学内容；确认正式知识库。
2. 引入账户与服务端学习记录，保持原有游客模式可用。
3. 以新模块接入 Spring AI，将知识解释、知识检索和复习建议接在业务 Service 之后。根据当时稳定版本重新检查 Java/Spring 兼容性。
4. 提供只读知识查询和学习记录查询工具；学习计划写入需要认证与权限检查，模型不能绕过规则修改进度。
5. 故事草稿进入 DRAFT 审核流程，模型生成不能自动标成 REVIEWED / PUBLISHED。AI 审核只能作为辅助。

## 约束

- 内容引用必须指向已有可验证来源；不生成教材页码或伪称考研真题。
- 学习解释与确定性判分分开，正确答案始终由受控知识内容和服务端规则决定。
- 区分生活类比与真实结构；复杂度必须附带模型与操作条件。
- 私有学习记录只在授权范围内提供给模型，设置调用超时、费用和日志脱敏边界。
- 持续用事实准确性、答案泄露、提示注入和进度误写用例验证效果；无需为未来可能性现在创建空类或空接口。
